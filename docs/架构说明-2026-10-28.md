# 天天记账 · 架构说明（2026-10-28 重构后）

> 这份文档写给「以后要改这个项目的人」看——包括几个月后的你自己。
> 目的只有一个：想加个功能时，知道该动哪个文件，不用再把整个项目读一遍。

---

## 一、这次重构干了什么

**一句话：把三个大文件（`main.js` 6.5KB、`db.js` 214 行、`renderer.js` 925 行）按职责拆成小组件，行为一点没变。**

拆之前的问题不是「代码写得烂」，而是「挤」：

| 拆之前 | 拆之后 | 为什么 |
|---|---|---|
| `main.js` 里同时有窗口、数据库、CSV 导出、生命周期 | `main/` 下 7 个文件 | 想改导出，得先穿过窗口代码 |
| `db.js` 一个文件管建表 + 增删改查 + 统计 | `db/` 下 7 个文件 | 找「趋势怎么算」要翻 150 行 |
| `renderer.js` 925 行塞了 5 个页面 + 弹窗 + 图表 | `src/lib/` 4 个 + `src/pages/` 5 个 + `features/` 1 个 + `app.js` | 五个页面共用一个文件里的全局变量，改一处怕碰坏另一处 |

**没改的**：界面长什么样、数据表结构（`records` 的字段一个没动）、依赖（还是只有 better-sqlite3，没加任何库）、Electron 版本。

## 二、目录地图（每个文件管什么）

```
main.js                 入口，只有一行：require('./main/app').start()

main/                   主进程（有完整 Node 权限的那一侧）
  app.js                开机流程：单实例锁 → 开日志 → 备份账本 → 打开账本 → 注册通道 → 开窗口
  dialogs.js            两段「弹框选文件」的流程（挑一份备份来恢复、挑一张 CSV 来导入）
  window.js             建窗口 + 三个安全开关（contextIsolation / nodeIntegration / sandbox）
  ipc.js                界面能调的所有能力，一张表注册；参数先过 validate
  validate.js           数据检查站：字段白名单、金额、日期、长度、范围
  channels.js           通道清单（唯一真源，preload 和 ipc 都照它来）
  paths.js              账本/备份/日志/最高分分别放在哪、旧账本（黑马记账）怎么搬过来
  export-csv.js         CSV 导出；buildCsv 是纯函数，可以脱离 Electron 单测
  import-csv.js         CSV 导入：自己写解析器（引号/逗号/BOM/换行都认）+ 按内容去重
  backup.js             每日自动备份（同一天一次，留 7 份）、手动备份、恢复、恢复前存现场
  logger.js             日志：接管 console 写文件、按天分文件留 7 天、兜住未捕获异常

db/                     数据层（唯一写 SQL 的地方）
  index.js              对外大门，保留原 API（init/close/addRecord/...）
  connection.js         打开账本、PRAGMA、执行迁移
  migrations.js         结构升级清单（第 1 步建表、第 2 步加索引）
  records.js            记一笔 / 改一笔 / 删一笔 / 查账
  stats.js              月度汇总、分类占比、趋势、日期范围
  month.js              「某年某月」→ 日期范围
  row.js                数据库一行 ↔ 界面对象（amount_cents → amountCents）

score.js                贪吃蛇最高分（跟账本完全隔离的小 json 文件）
preload.js              安全桥：只开 13 个口子，界面拿不到 fs

src/
  index.html            页面骨架；脚本按「工具 → 零件 → 装配」顺序加载
  app.js                界面总调度：切页面、refreshAll
  lib/dom.js            找元素、转义、轻提示
  lib/format.js         分↔元、日期、图表刻度
  lib/categories.js     收入/支出分类表 + 图标
  lib/charts.js         环形图、柱状趋势图（手绘 SVG，没引图表库）
  pages/overview.js     概览页
  pages/bills.js        账单页（按月 + 筛选 + 改/删）
  pages/stats.js        统计页（三图 + 趋势范围）
  pages/settings.js     设置页（导出 + 关于）
  pages/game.js         小游戏页（画面/键盘/音效；规则在 snake-core.js）
  features/add-record.js 记一笔弹窗（新增与修改共用）
  snake-core.js         贪吃蛇纯规则（不含界面，可 node 单测）
  dev-mock.js           预览用假桥：浏览器直接打开 index.html 时有假数据；正式软件里自动让位
```

## 三、记一笔，数据是怎么走的

```
点「保存」
  → features/add-record.js 把金额折成「分」，凑成一个对象
  → preload.js: window.tiantian.addRecord(record)      ← 唯一通道
  → main/ipc.js: 先过 validate.record()，不合格直接报错，进不了数据库
  → db/records.js: prepare(...).run(...)               ← 参数化，不拼字符串
  → records 表
  → 返回整条记录
  → app.js 的 refreshAll()：首页必刷，账单/统计页正显示着才刷
```

**为什么校验放在主进程而不是只放界面**：界面那道检查是为了让人少走冤枉路；真正防脏数据的是主进程这道。旧版本只有界面检查，等于没锁门。

## 四、三条规矩（以后加功能照着做）

### 1. 加一个界面功能

- 在某个页面上加东西 → 只改 `src/pages/那个页面.js`，样式进 `styles.css`
- 页面要取数据 → 用现成的 `window.tiantian.xxx()`；没有的话看第 2 条
- 页面之间**不要互相调用**。数据变了就调 `TT.refreshAll()`，让各页面自己刷
- **新增文件必须同时往 `index.html` 加 `<script>`**，顺序是 lib → snake-core → pages → features → app.js。
  加完跑 `node test/renderer-manifest.test.js`：文件漏引、顺序错、名字挂错都会红

### 2. 加一个数据接口（界面要读新数据）

必须同时改三处，少一处就会出现「点了没反应」：

1. `main/channels.js` 加一行通道名
2. `main/ipc.js` 的 `handlers` 表里实现它（**记得先 validate**）
3. `preload.js` 加一个方法去 `ipcRenderer.invoke` 它

改完跑 `node test/ipc-contract.test.js`——它会核对三处是否一致，漏了会红。

### 3. 改表结构（加字段、加表）

1. 在 `db/migrations.js` 数组**末尾**追加一条，`version` 递增，**不要改已经发出去的那几条**
2. `up` 里只做加法（加表/加列/加索引），不删用户数据
3. 跑 `node test/migration.test.js`——它会模拟一本老账本，验证升级后数据一条不少

> 为什么不能直接改 `CREATE TABLE`：用户电脑里那本账已经存着真实数据，
> `CREATE TABLE IF NOT EXISTS` 对已存在的表什么都不做，改了等于没改。

## 五、测试怎么跑

```bash
# 一、纯逻辑（node 直接跑，零依赖，168 条断言）
node test/snake-core.test.js        # 贪吃蛇规则
node test/score.test.js             # 最高分读写
node test/db.test.js                # 账本增删改查
node test/validate.test.js          # 数据检查站
node test/export-csv.test.js        # CSV 拼装（乱码/BOM/转义）
node test/import-csv.test.js        # CSV 解析与导入（引号/逗号/换行/去重）
node test/backup.test.js            # 备份与恢复（节流、只留 7 份、拒绝坏文件）
node test/paths.test.js             # 账本路径 + 旧账本搬家（别覆盖用户新账）
node test/format.test.js            # 分↔元、刻度取整（给用户看的钱不能错）
node test/renderer-manifest.test.js # 界面装配：脚本齐全、顺序对、无孤儿文件
node test/ipc-contract.test.js      # 三处通道是否对得上
node test/migration.test.js         # 老账本升级不丢数据

# 二、界面冒烟（离屏渲染真界面，不弹窗，24 项断言 + 截图到 test/artifacts/）
./node_modules/.bin/electron --disable-gpu test/ui-smoke.js

# 三、整机开机（真 preload + 真通道 + 真 SQLite，23 项断言）
./node_modules/.bin/electron --disable-gpu test/app-boot.test.js
```

两套 Electron 测试都用**临时 userData**，绝不动真实的 `tiantian.db`。

## 五之二、数据存在哪（出问题时先看这里）

| 东西 | 位置 | 说明 |
|---|---|---|
| 账本 | `%APPDATA%\天天记账\tiantian.db` | 唯一真数据，备份就是复制它 |
| 每日备份 | `%APPDATA%\天天记账\backups\tiantian-YYYYMMDD-HHmmss.db` | 每天第一次开软件时自动存，留 7 份 |
| 恢复前现场 | `%APPDATA%\天天记账\backups\tiantian-before-restore-*.db` | 每次恢复前自动存，留 3 份 |
| 日志 | `%APPDATA%\天天记账\logs\main-YYYY-MM-DD.log` | 留 7 天；界面报的错也写这儿 |
| 最高分 | `%APPDATA%\天天记账\snake_highscore.json` | 跟账本完全隔离 |

> 顺序很重要：**备份发生在「打开账本」之前**。所以每天那份一定是「当天动过之前」的原样，
> 万一结构升级出岔子，手里这份能原封不动换回去。这个顺序有测试守着
> （`backup.test.js` 的「备份文件是真能打开的账本」+ 用真实账本副本做过的顺序演练）。

## 六、明确还没做的（别以为忘了）

| 事项 | 为什么没做 | 要做的话在哪下手 |
|---|---|---|
| 用户自定义分类 | 这是 v1.2 的产品功能，不是重构范围 | 加 `categories` 表 + 迁移，再把 `lib/categories.js` 改成从主进程读 |
| 暗色模式 | CLAUDE.md 里定的是后期可选 | 主要动 `styles.css` 的 CSS 变量 |
| Mac 版打包 | 必须在 Mac 上打 | `package.json` 的 build 配置已就绪 |
| 自动备份到 U 盘 / 网盘 | 产品上没定；本机备份已经能救命 | `main/backup.js` 的 `copyTo` 旁边加一个「额外目标目录」 |
| CLAUDE.md 里的目录说明 | 按项目规矩，改那份文档要先经你同意 | 等你点头 |

## 七、和旧结构的对照

| 旧 | 新 |
|---|---|
| `main.js`（6.5KB，窗口+DB+导出+生命周期） | `main/` 7 个文件 |
| `db.js`（214 行） | `db/` 7 个文件 + `db/index.js` 大门 |
| `src/renderer.js`（925 行，5 个页面） | `src/lib/` 4 个 + `src/pages/` 5 个 + `src/features/` 1 个 + `src/app.js` |
| `src/snake-game.js` | `src/pages/game.js` |
| 界面各页面互相调用函数 | 统一走 `TT.refreshAll()` |
| `preload.js` 写死 `appVersion: '0.1.0'` | 主进程按 `package.json` 提供，永不打架 |
| 启动失败静默闪退 | 弹对话框说人话再退出 |
| 没有任何索引 | `date`、`type+date` 两个索引 |
| 没有升级机制 | `user_version` + 迁移清单 |
| 账本只有一份，丢了就没了 | 每天自动备份，留 7 份；恢复前还会存现场 |
| CSV 只能出不能回 | 支持导入，按内容去重，同一张表导两遍也不会重复 |
| 出问题只能看控制台 | 日志按天落文件（`logs/`），界面报的错也写进去 |
