## 四、🧹 代码质量报告

### 4.1 客观数据

- 通读文件数：13 个代码文件（另含 index.html / styles.css / package.json 作为辅助参考）
- 问题总数：**8 处**（命名 2 ｜ 错误处理 3 ｜ 死代码/重复 3）

### 4.2 需要改进的地方

#### 命名规范（2 处）

- **src/renderer.js:813**（`y` 函数）：单字母名字，不看上下文猜不出是「把金额换算成画布纵坐标」。建议改叫 `yOf(cents)` 或 `toY(cents)`，或者至少加一行注释。→ 低
- **main.js:115**（`esc` 函数）：缩写是 `escape` 的缩略，配合 CSV 上下文能猜出来，但小白第一眼会愣一下。建议直接叫 `escapeCsvCell`。→ 低

#### 错误处理（3 处）

- **main.js:40-57**（`setupDatabase` / `migrateOldDatabase`）：这两段「碰文件」的启动代码没有 try/catch 兜底。如果旧「黑马记账」账本文件被占用或损坏，`fs.copyFileSync` 或 `db.init` 报错时，软件会**直接打不开、也没有友好提示**。建议包一层 try/catch，失败时弹个窗口告诉用户「账本没打开成功」。→ 中低
- **src/renderer.js:780**（`setTrendQuick` 的「全部」分支）：`await window.tiantian.getDateRange()` 这一句没在 try/catch 里（旁边的 `renderTrendRange` 反而包了），万一接口异常会变成「没人接住的报错」。建议把这句也包进 try。→ 低
- **start.js:19**（`spawn` 启动 Electron）：只监听了 `close`，没监听 `error`。如果 Electron 程序本身起不来，`error` 事件没人接，进程可能直接退出且无提示。建议加一个 `child.on('error', ...)` 打一行说明。→ 低

#### 死代码 / 重复代码（3 处）

- **src/renderer.js:616**（`DONUT_COLORS` 色板）：定义了 8 个颜色，但环形图实际只用到前 5 个（`cats.slice(0,5)` 配 `DONUT_COLORS[i]`），剩下 3 个颜色（`#008300`、`#4a3aa7`、`#e34948`）**从没被用过**，是「死数据」。建议删到只剩 5 个，或将来真画更多段时再用。→ 低
- **src/renderer.js:381-396 与 551-566**（账单页/统计页的月份切换）：`initBillsMonth` 和 `initStatsMonth` 几乎一模一样，`shiftBillsMonth` 和 `shiftStatsMonth` 也只差最后调用的函数。两套可以合并成一个通用的「月份状态器」，改一处就行、不会改漏。→ 低
- **db.js:88-96 / 113-119 / 123-133**（三个月度查询的起点终点）：`getMonthlySummary`、`getRecordsByMonth`、`getCategoryTotals` 里都重复写「本月 1 号 = start、下月 1 号 = end」这两行。建议抽一个 `monthRange(year, month)` 小工具，三处共用。→ 低

### 4.3 做得好的地方（点名表扬）

- **错误兜底覆盖面广**：界面所有数据库操作（记一笔、改、删、查、导出）都包了 try/catch，失败会弹 toast 提示「保存失败」，不会「安静坏掉」。
- **score.js 容错极佳**：最高分文件不存在、内容损坏、不是数字，一律安全返回 0，绝不崩溃；写失败如实报告 `ok:false`，界面不假装成功。
- **命名整体清晰**：变量名基本是「一看就懂」的中文场景英文名（`amountCents`、`categoryMain`、`records`），没有发现同一东西两种写法的混用。
- **snake-core.js 与 snake-game.js 分工干净**：规则纯逻辑与界面完全分离，规则可单独用 node 测试，边界情况（撞墙、撞自己、胜利）都处理了，还防了「一帧内连按两个方向被吞」的坑。
- **启动迁移有护栏**：`migrateOldDatabase` 先检查新位置有没有账本、没有再搬，避免覆盖已有数据。
- **趋势图防死循环**：`getMonthlyTrendRange` 里设了「上限 100 年」的 guard，万一月份循环出 bug 也不会卡死。

### 4.4 下一步建议

- 优先级最高的是 **main.js 启动环节的 try/catch**（第 40-57 行），因为它关系到「万一出问题软件能不能打开」。
- 其余 7 处都是低优先级的小优化，攒着以后一起改也行，不影响当前使用。
