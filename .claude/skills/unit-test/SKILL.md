# 单元测试工作手册（天天记账专用）

## 这本手册管什么
只做三件事：**出题 → 答题 → 交成绩单**。
- 出题 = 把「某个小零件应该怎么工作」写成一道道考题，存进 test/ 文件夹
- 答题 = 跑命令，让代码自动做考题
- 成绩单 = 汇总「几道过、几道没过、为什么没过」，**只在屏幕汇报，不存文件**

不修改生产代码，除非用户明确要求修 Bug。

## 第一步 摸底（先看要测谁）
1. 用 Glob 列出根目录和 src/ 的 .js 文件（跳过 node_modules/）。
2. 分辨「纯逻辑模块」：不依赖 Electron 窗口、能用 node 直接 require。本项目已知：
   - `db.js` 记账数据库（需「临时数据库文件」才能测，见红线）
   - `score.js` 贪吃蛇最高分读写
   - `src/snake-core.js` 贪吃蛇核心逻辑
3. 看一眼 test/ 目录有哪些考题册，避免重复出题。
4. 界面代码（src/renderer.js、src/snake-game.js、main.js 的窗口部分）需要 Electron 窗口，本手册默认不测；除非用户明确要求。

## 第二步 出题（写考题册）
- 文件放 test/，命名 xxx.test.js，一本考题册只考一个零件。
- 风格统一：用 node 自带的 assert + check(name, fn) 小帮手；每道题先写一句大白话名字。
- 文件末尾打印：`console.log(\`\n${passed} 项测试全部通过\`)`。
- 考点覆盖：正常情况、边界情况（空/0/最大）、非法输入、报错场景。
- 测试数据一律用「临时文件」，绝不用真实数据。

## 第三步 执行（答题）
- 纯逻辑考题：`node test/xxx.js`（Git Bash 里跑）。
- 需要 Electron 的（本手册一般不碰）：用独立临时 userData 冒烟测试，命令形如
  `env -u ELECTRON_RUN_AS_NODE -u ELECTRON_FORCE_RENDERER_ACCESSIBILITY ./node_modules/.bin/electron --disable-gpu --user-data-dir=<临时目录> test/xxx.js`

## 第四步 成绩单（屏幕汇报）
1. 每本考题册一行：共几道、过几道、没过几道。
2. 没过的题：点名 + 最可能的原因 + 相关代码位置。
3. 全过就一句大白话总结（例：「全项目 34 道题全部通过，账本和贪吃蛇都健康」）。
4. 顺带提示「还有哪些零件没有考题」，但不擅自出题，先问用户。

## 红线（绝不能违反）
- **绝不碰真实账本数据**：测试数据库必须在系统临时目录（os.tmpdir()）建临时文件，测完删除；冒烟测试必须用独立临时 userData，绝不加载真实 userData（那里有用户的 tiantian.db 和 snake_highscore.json）。
- 不扩大功能范围：不碰用户没要求测的领域。
- 执行命令一条一条跑，不用长 && 拼接。
